# Exporters — Utility Documentation

> **Location:** `src/utils/exporters/`  
> **Type:** Pure Utility Functions — TypeScript  
> **Purpose:** A collection of six export modules that convert Modellr's internal canvas state (tables + relationships) into external formats. Each exporter produces a specific output format used in the "Export" feature of the editor.

---

## Overview — Exporter Directory

| File | Function | Output Format | Description |
|---|---|---|---|
| `sql.ts` | `exportSQL` | PostgreSQL/MySQL DDL | `CREATE TABLE` statements with FK constraints |
| `prisma.ts` | `exportPrisma` | Prisma Schema | Full `schema.prisma` with models and relations |
| `drizzle.ts` | `exportDrizzle` | Drizzle ORM TypeScript | `pgTable()` definitions with typed relations |
| `dbml.ts` | `exportDBML` | DBML | Database Markup Language for documentation tools |
| `migrations.ts` | `generateMigrationsSQL` | SQL Migration Script | `ALTER TABLE`/`CREATE TABLE`/`DROP TABLE` diff-based migration |
| `image.ts` | `exportImage` | PNG / SVG | Canvas snapshot via `html-to-image` |

All exporters (except `image.ts`) are **pure functions** — no side effects, no DOM access, no I/O. They accept tables and relationships and return a string. `image.ts` is async and interacts with the DOM.

# `sql.ts` — SQL DDL Exporter

> **Location:** `src/utils/exporters/sql.ts`

## File Overview

Generates standard PostgreSQL-compatible `CREATE TABLE` DDL SQL from the canvas state. Produces one `CREATE TABLE` block per table, with inline column definitions and table-level `FOREIGN KEY` constraints. This is the front-end equivalent of `server/utils/sqlExporter.js` — but **does not contain the syntax bug** present in the server version.

## Dependencies & Imports

```ts
import type { Table, Relationship, Dialect } from '../../types/schema';
```

No external dependencies — pure string concatenation.

## Exported Function — `exportSQL`

**Signature:**
```ts
export function exportSQL(tables: Table[], relationships: Relationship[], dialect: Dialect): string
```

| Parameter | Type | Description |
|---|---|---|
| `tables` | `Table[]` | Canvas table objects |
| `relationships` | `Relationship[]` | FK relationship objects |
| `dialect` | `Dialect` | Dialect token used only in the header comment; SQL is always PostgreSQL-style |

> **Note:** The `dialect` parameter is accepted but **only used in the header comment**. The generated SQL is identical regardless of dialect — always PostgreSQL-style with double-quoted identifiers.

## Constraint Helper Functions

```ts
const NULLABLE = (nullable: boolean) => (nullable ? '' : ' NOT NULL');
const UNIQUE   = (unique: boolean)   => (unique ? ' UNIQUE' : '');
const DEFAULT  = (def?: string)      => (def ? ` DEFAULT ${def}` : '');
const CHECK    = (check?: string)    => (check ? ` CHECK (${check})` : '');
```

These are **identical in intent** to those in `server/utils/sqlExporter.js`, but here the `DEFAULT` call is correctly written as `${DEFAULT(f.default)}` — **the syntax bug present in the server version does not exist here**.

## `fieldDDL(f)` — Column Definition Renderer

```ts
function fieldDDL(f: Table['fields'][0]): string {
  const pk = f.isPK ? ' PRIMARY KEY' : '';
  return `  "${f.name}" ${f.type}${NULLABLE(f.nullable)}${UNIQUE(f.unique)}${DEFAULT(f.default)}${CHECK(f.check)}${pk}`;
}
```

Renders a single column line in the format:
```sql
  "column_name" type [NOT NULL] [UNIQUE] [DEFAULT val] [CHECK (expr)] [PRIMARY KEY]
```

## Data Lookups

```ts
const tableMap = new Map(tables.map(t => [t.id, t]));
const fieldMap = new Map(tables.flatMap(t => t.fields.map(f => [`${t.id}:${f.id}`, { table: t, field: f }])));
```

- **`tableMap`**: `Map<tableId, Table>` — O(1) table lookup by ID for FK resolution.
- **`fieldMap`**: `Map<"tableId:fieldId", {table, field}>` — O(1) field lookup using composite key.

## Output Format

```sql
-- Generated by Modellr
-- Dialect: postgres
-- 2026-04-11T09:25:39.000Z

CREATE TABLE "users" (
  "id" bigserial NOT NULL PRIMARY KEY,
  "email" text NOT NULL UNIQUE
);

CREATE TABLE "orders" (
  "id" bigserial NOT NULL PRIMARY KEY,
  "user_id" bigint NOT NULL,
  FOREIGN KEY ("user_id") REFERENCES "users" ("id")
);
```

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **No topological sort** | Tables emitted in array order — FK target tables must appear before FK source tables in the input, or the SQL will fail at runtime |
| **`dialect` param unused in logic** | Only written into the header comment |
| **No `IF NOT EXISTS`** | Re-running the SQL on an existing DB errors |
| **Default value not quoted** | String defaults must already be pre-quoted in the field data |
| **`CHECK` support** | Fully supported in the client exporter (unlike the server version) |

# `prisma.ts` — Prisma Schema Exporter

> **Location:** `src/utils/exporters/prisma.ts`

## File Overview

Converts the canvas state into a valid **Prisma schema file** (`schema.prisma`). Generates a complete file including `generator client`, `datasource db`, and `model` blocks for every table — with field types, attributes, relation fields, and back-relation fields.

## Dependencies & Imports

```ts
import type { Table, Relationship } from '../../types/schema';
```

No external dependencies.

## Exported Function — `exportPrisma`

**Signature:**
```ts
export function exportPrisma(tables: Table[], relationships: Relationship[]): string
```

## Output Structure

```prisma
// Generated by Modellr
// https://Modellr.dev

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Users {
  id          BigInt    @id @default(autoincrement())
  email       String    @unique
  orders      Orders[]
}

model Orders {
  id          BigInt    @id @default(autoincrement())
  user_id     BigInt
  users       Users     @relation(fields: [user_id], references: [id])
}
```

## Generation Logic

1. **Header comments + config blocks** (lines 10–21) — always emitted.
2. **FK lookup map** (lines 24–30) — builds `Map<fieldId, targetTableName>` for O(n) FK resolution.
3. **Per-table model block** (lines 32–81):
   - Table name → PascalCase model name via `toPascalCase()`
   - Each field: Prisma type, optional `?`, and attributes (`@id`, `@unique`, `@default(...)`)
   - FK fields get an inline **relation object field** (e.g. `users Users @relation(fields: [user_id], references: [id])`)
   - Back-relations from `incomingRels` — adds `srcModels SrcModel[]` or `srcModel SrcModel?` fields

## Helper Functions

### `toPascalCase(name: string): string`

```ts
name.split(/[_\s-]+/).map(w => w.charAt(0).toUpperCase() + w.slice(1).toLowerCase()).join('')
```

- `user_profile` → `UserProfile`
- `order-item` → `OrderItem`
- Splits on `_`, space, and `-`

### `toPrismaType(sqlType: string): string`

Full SQL → Prisma type mapping:

| SQL Type(s) | Prisma Type |
|---|---|
| `integer`, `int`, `int4`, `smallint`, `serial`, `tinyint` | `Int` |
| `bigint`, `int8`, `bigserial`, `serial8` | `BigInt` |
| `real`, `float4`, `double precision`, `float8` | `Float` |
| `decimal`, `numeric`, `money` | `Decimal` |
| `varchar`, `nvarchar`, `char`, `text`, `longtext`, etc. | `String` |
| `boolean`, `bool`, `bit` | `Boolean` |
| `timestamp`, `timestamptz`, `datetime`, `date` | `DateTime` |
| `time`, `timetz` | `String` |
| `uuid`, `uniqueidentifier` | `String` |
| `json`, `jsonb` | `Json` |
| `bytea`, `binary`, `blob`, `image` | `Bytes` |
| anything else | `String` (fallback) |

### `isPrismaAutoType(sqlType: string): boolean`

Returns `true` for `serial`, `bigserial`, `smallserial`, `serial4`, `serial8` — these emit `@default(autoincrement())`.

### `formatPrismaDefault(def: string): string`

Converts SQL default values to Prisma format:

| SQL Default | Prisma Default |
|---|---|
| `now()`, `current_timestamp` | `now()` |
| `true`, `false` | `true`, `false` |
| `null` | `""` (empty — omitted) |
| numeric literals | passed through |
| `'string'` (SQL string) | `"string"` (Prisma string) |
| other | wrapped in `"..."` |

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **Back-relation pluralization** | `one-to-many` → `srcModels` (plural `s`), `one-to-one` → `srcModel?` (optional) |
| **`uuid` → `String`** | Prisma doesn't have a native UUID type — maps to `String`. The `@default(uuid())` is added separately. |
| **Always PostgreSQL datasource** | `provider = "postgresql"` is hardcoded — no other dialect output |
| **`references: [id]`** | Relation references always target `id` — not the actual `targetField` from the relationship endpoint |
| **Field name padding** | `.padEnd(20)` creates column-aligned output in the model file |

# `drizzle.ts` — Drizzle ORM Exporter

> **Location:** `src/utils/exporters/drizzle.ts`

## File Overview

Generates **Drizzle ORM TypeScript definitions** for the PostgreSQL adapter (`drizzle-orm/pg-core`). Produces `pgTable()` column definitions and `relations()` blocks for the full schema.

## Dependencies & Imports

```ts
import type { Table, Relationship, Field } from '../../types/schema';
```

No external dependencies.

## Exported Function — `exportDrizzle`

**Signature:**
```ts
export function exportDrizzle(tables: Table[], relationships: Relationship[]): string
```

## Output Structure

```ts
// Generated by Modellr
// https://Modellr.dev

import { pgTable, serial, integer, text, varchar, boolean, timestamp, numeric, jsonb, uuid, foreignKey, index } from 'drizzle-orm/pg-core';
import { relations } from 'drizzle-orm';

export const usersTable = pgTable('users', {
  id: serial('id').primaryKey(),
  email: varchar('email').notNull().unique(),
  created_at: timestamp('created_at', { withTimezone: true }).defaultNow(),
});

/** Relations */
export const usersTableRelations = relations(usersTable, ({ one, many }) => ({
  orders: many(ordersTable),
}));

export const ordersTable = pgTable('orders', {
  id: serial('id').primaryKey(),
  user_id: integer('user_id').notNull(),
});

export const ordersTableRelations = relations(ordersTable, ({ one, many }) => ({
  users: one(usersTable, {
    fields: [ordersTable.user_id],
    references: [usersTable.id]
  }),
}));
```

## `buildDrizzleField(field: Field): string`

The core helper that generates a Drizzle column definition chain:

### Type Mapping

| Field Type | Drizzle Builder | Notes |
|---|---|---|
| `serial`, `integer` (PK) | `serial('name')` | Auto-upgrades int PKs to serial |
| `integer`, `int` (non-PK) | `integer('name')` | |
| `bigserial` | `bigserial('name')` | (not imported by default — may need adding) |
| `bigint` | `bigint('name', { mode: 'number' })` | mode forces JS number |
| `varchar(N)` | `varchar('name', { length: N })` | Extracts size param |
| `varchar` (no size) | `varchar('name')` | |
| `boolean` | `boolean('name')` | |
| `timestamp`, `timestamptz` | `timestamp('name', { withTimezone: true })` | `tz` suffix triggers `withTimezone` |
| `decimal`, `numeric` | `numeric('name')` | |
| `json`, `jsonb` | `jsonb('name')` | |
| `uuid` | `uuid('name')` | |
| anything else | `text('name')` | fallback |

### Modifier Chain

```ts
serial('id').primaryKey()
varchar('email').notNull().unique()
timestamp('created_at', { withTimezone: true }).defaultNow()
integer('count').notNull().default(0)
```

### Default Value Mapping

| Field default | Drizzle chain |
|---|---|
| `now()`, `current_timestamp` | `.defaultNow()` |
| `uuid_generate_v4()` | `.defaultRandom()` |
| Numeric / `true` / `false` | `.default(value)` |
| Other string | `.default('stripped_value')` |

## Relations Generation

### Outgoing (FK source — `one()`)

```ts
export const ordersTableRelations = relations(ordersTable, ({ one }) => ({
  users: one(usersTable, {
    fields: [ordersTable.user_id],
    references: [usersTable.id]
  }),
}));
```

Field names are resolved from `table.fields.find(f => f.id === rel.sourceFieldId)`.

### Incoming (FK target — `many()` or `one()`)

```ts
  orders: many(ordersTable),     // one-to-many
  order: one(ordersTable),       // one-to-one (no plural 's')
```

Back-relation field name is `sourceTable.name + 's'` for `one-to-many`, or `sourceTable.name` for `one-to-one`.

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **Dead code on line 52** | `lines.push(\`fields: [${constName}.${rel.sourceFieldId}]\`)` — this pushes a line using the UUID `sourceFieldId`, then the next block (lines 54–59) correctly resolves and pushes the actual field name. The UUID line is a **bug** — it emits incorrect code before the correct line. |
| **`bigserial` not in import** | The import statement on line 10 doesn't include `bigserial` but the field builder emits `bigserial(...)` — would cause a runtime import error if used |
| **`foreignKey`, `index` imported but unused** | These are in the import statement (line 10) but never called in the output |
| **`int` PK → `serial`** | Integer PKs are automatically upgraded to `serial` — assumes auto-increment, which may not always be correct |
| **Cardinality-based pluralization** | `one-to-many` back-relation name gets `'s'` appended — `orders` not `order`. Hard-coded pluralization may be wrong for irregular nouns |

# `dbml.ts` — DBML Exporter

> **Location:** `src/utils/exporters/dbml.ts`

## File Overview

Generates **Database Markup Language (DBML)** — a plain-text schema format popularized by [dbdiagram.io](https://dbdiagram.io). DBML is used for documentation, visualization in third-party tools, and sharing schema definitions in a human-readable format.

## Dependencies & Imports

```ts
import type { Table, Relationship } from '../../types/schema';
```

No external dependencies.

## Exported Function — `exportDBML`

**Signature:**
```ts
export function exportDBML(tables: Table[], relationships: Relationship[]): string
```

## Output Format

```dbml
// Generated by Modellr
// 2026-04-11T09:25:39.000Z

Table users {
  id bigserial [pk, not null]
  email varchar [not null, unique]
  created_at timestamptz [not null, default: `now()`]
}

Table orders {
  id bigserial [pk, not null]
  user_id bigint [not null]
}

Ref: orders.user_id > users.id
```

## Generation Logic

### Table Blocks

```ts
tables.map(table => {
  const fields = table.fields.map(f => {
    const opts = [];
    if (f.isPK)      opts.push('pk');
    if (!f.nullable) opts.push('not null');
    if (f.unique)    opts.push('unique');
    if (f.default)   opts.push(`default: \`${f.default}\``);
    if (f.comment)   opts.push(`note: '${f.comment}'`);
    return `  ${f.name} ${f.type}${opts.length ? ` [${opts.join(', ')}]` : ''}`;
  });
  return `Table ${table.name} {\n${fields.join('\n')}\n}`;
});
```

### Reference Statements

```ts
const arrow = r.cardinality === 'one-to-many'  ? '>'  :
              r.cardinality === 'many-to-many' ? '<>' : '-';
return `Ref: ${sourceTable}.${sourceField} ${arrow} ${targetTable}.${targetField}`;
```

| Cardinality | DBML Arrow |
|---|---|
| `one-to-many` | `>` |
| `many-to-many` | `<>` |
| `one-to-one` | `-` |

## `fieldMap` for Ref Resolution

```ts
const fieldMap = new Map(
  tables.flatMap(t => t.fields.map(f => [`${t.id}:${f.id}`, { table: t, field: f }]))
);
```

Composite key `"tableId:fieldId"` enables O(1) field + table name lookup for `Ref:` statements.

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **`f.comment` support** | DBML `note:` is emitted if `field.comment` exists — but `comment` is not a standard `Field` property (checked via duck typing) |
| **No table-level notes** | DBML supports `Note: '...'` on tables — not implemented |
| **Default backtick wrapping** | DBML uses `` `expression` `` for default expressions — correctly wrapped in backticks |
| **Tables before Refs in output** | All `Table` blocks first, then a blank line, then all `Ref:` statements — valid DBML ordering |
| **Filter Boolean on refs** | `filter(Boolean)` removes `null` returns where source/target fields can't be resolved |

# `migrations.ts` — SQL Migration Generator

> **Location:** `src/utils/exporters/migrations.ts`

## File Overview

Generates SQL migration scripts from a **diff** between two schema states. Unlike other exporters that take raw `tables` and `relationships`, this one takes a structured `TableDiff[]` array and a `Dialect` — producing targeted `DROP TABLE`, `ALTER TABLE`, and `CREATE TABLE` statements in the correct dependency-safe order.

## Dependencies & Imports

```ts
import type { Dialect, Field, Table } from '../../types/schema';
```

No external dependencies.

## Exported Types

### `FieldDiff`

```ts
export type FieldDiff =
  | { kind: 'added';   field: Field }
  | { kind: 'removed'; field: Field }
  | { kind: 'changed'; before: Field; after: Field };
```

### `TableDiff`

```ts
export type TableDiff =
  | { kind: 'added';   table: Table }
  | { kind: 'removed'; table: Table }
  | { kind: 'changed'; tableName: string; fields: FieldDiff[] };
```

These discriminated union types are the **input contract** — callers compute diffs externally and pass them in.

## Exported Function — `generateMigrationsSQL`

**Signature:**
```ts
export function generateMigrationsSQL(diffs: TableDiff[], dialect: Dialect): string
```

| Parameter | Type | Description |
|---|---|---|
| `diffs` | `TableDiff[]` | Array of table-level diff entries |
| `dialect` | `Dialect` | `'postgres'` or `'mysql'` — affects identifier quoting and ALTER syntax |

**Returns:** A SQL migration string, or `'-- No schema changes detected.'` if `diffs` is empty.

## Quoting Helper

```ts
function quote(name: string, dialect: Dialect): string {
  return dialect === 'postgres' ? `"${name}"` : `\`${name}\``;
}
```

| Dialect | Quoting |
|---|---|
| `postgres` | `"name"` |
| `mysql` | `` `name` `` |

## Field Definition Helper

```ts
function getFieldDef(f: Field, dialect: Dialect): string {
  let def = `${quote(f.name, dialect)} ${f.type}`;
  if (!f.nullable) def += ' NOT NULL';
  if (f.unique && !f.isPK) def += ' UNIQUE';
  if (f.isPK) def += ' PRIMARY KEY';
  return def;
}
```

Note: `DEFAULT` is **not emitted** by this helper — no default values in migration column additions.

## SQL Generation — Three-Phase Order

### Phase 1 — DROP TABLE (removed tables first)

```sql
DROP TABLE "legacy_table";
```

Drops happen **first** to avoid FK dependency conflicts when the new schema is created.

### Phase 2 — ALTER TABLE (changed tables)

Three sub-operations per changed table:

**ADD COLUMN:**
```sql
ALTER TABLE "users"
  ADD COLUMN "phone" text;
```

**DROP COLUMN:**
```sql
ALTER TABLE "users"
  DROP COLUMN "legacy_field";
```

**MODIFY/ALTER COLUMN (dialect-sensitive):**
```sql
-- PostgreSQL:
ALTER TABLE "orders"
  ALTER COLUMN "total" TYPE numeric USING "total"::numeric;

-- MySQL:
ALTER TABLE `orders`
  MODIFY COLUMN `total` numeric NOT NULL;
```

PostgreSQL: Uses `ALTER COLUMN ... TYPE` with an optional `USING` cast clause (added for `char`/`text` target types).
MySQL: Uses `MODIFY COLUMN` with the full field definition.

### Phase 3 — CREATE TABLE (added tables last)

```sql
CREATE TABLE "tags" (
  "id" bigserial NOT NULL PRIMARY KEY,
  "name" text NOT NULL
);
```

Created **last** — ensures FK references from altered tables already exist.

## Output Example

```sql
-- Auto-generated migration for PostgreSQL

DROP TABLE "old_logs";

ALTER TABLE "users"
  ADD COLUMN "phone" text,
  DROP COLUMN "legacy_column",
  ALTER COLUMN "email" TYPE varchar USING "email"::varchar;

CREATE TABLE "tags" (
  "id" bigserial NOT NULL PRIMARY KEY,
  "name" text NOT NULL
);
```

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **DROP → ALTER → CREATE ordering** | Prevents FK conflicts during migration execution |
| **`USING` cast only for char/text targets** | Only text-type changes get a `USING` clause — other type changes (e.g. `integer` → `numeric`) may still fail without a cast |
| **No FK constraint migrations** | Relationship additions/removals are not handled — only table and column changes |
| **No `DEFAULT` in `ADD COLUMN`** | `getFieldDef()` doesn't include defaults — existing rows get `NULL` for nullable new columns, or error for `NOT NULL` columns |
| **No `IF EXISTS` / `IF NOT EXISTS`** | Non-idempotent — re-running will error |
| **No transaction wrapping** | Partial failure leaves DB in inconsistent state |

# `image.ts` — Canvas Image Exporter

> **Location:** `src/utils/exporters/image.ts`

## File Overview

The simplest exporter — captures a **PNG or SVG screenshot** of the React Flow canvas element and triggers a browser download. Uses `html-to-image` for DOM-to-image conversion.

## Dependencies & Imports

```ts
import { toPng, toSvg } from 'html-to-image';
```

| Import | Role |
|---|---|
| `toPng` | Converts a DOM element to a PNG data URL |
| `toSvg` | Converts a DOM element to an SVG data URL |

## Exported Function — `exportImage`

**Signature:**
```ts
export async function exportImage(format: 'png' | 'svg'): Promise<void>
```

| Parameter | Type | Description |
|---|---|---|
| `format` | `'png' \| 'svg'` | Output image format |

**Returns:** `Promise<void>` — triggers a file download as a side effect.  
**Throws:** If `.react-flow__renderer` element is not found in the DOM.

## Implementation

```ts
// 1. Find the canvas DOM element
const canvas = document.querySelector('.react-flow__renderer') as HTMLElement;
if (!canvas) throw new Error('Canvas not found');

// 2. Convert to data URL
const dataUrl = format === 'png'
  ? await toPng(canvas, { pixelRatio: 2, cacheBust: true })
  : await toSvg(canvas, { cacheBust: true });

// 3. Trigger download
const link = document.createElement('a');
link.href = dataUrl;
link.download = `schema.${format}`;
link.click();
```

## Options Used

| Option | Value | Effect |
|---|---|---|
| `pixelRatio: 2` | PNG only | Renders at 2× resolution for crisp output on HiDPI/Retina screens |
| `cacheBust: true` | Both | Appends a random query string to embedded image URLs to force cache bypass |

## Notable Patterns & Caveats

| | Detail |
|---|---|
| **DOM-dependent** | Only works in a browser context — cannot be called server-side or in tests without a DOM |
| **CSS variables may not render** | `html-to-image` may not capture CSS custom properties (`var(--color)`) correctly in all browsers |
| **Always named `schema.png` / `schema.svg`** | Download filename is hardcoded — no schema name or timestamp in the filename |
| **Throws on missing canvas** | If called before the canvas is mounted (or on a wrong page), throws synchronously |
| **No error handling returned** | The function throws directly rather than returning a rejected promise with a user-friendly message |
| **Link not cleaned up** | The `<a>` element is created but never appended to the DOM or removed — works via `.click()` but is a minor leak |
| **SVG has no `pixelRatio`** | SVGs are vector — `pixelRatio` is a no-op for SVG export |
